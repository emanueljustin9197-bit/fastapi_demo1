# 在线表格智能问卷系统功能需求说明书

> 文档编号：OF-SRS-001  
> 版本：V1.0（评审稿）  
> 日期：2026-09-18

## 1. 引言

### 1.1 编写目的

本文档定义在线表格智能问卷系统的业务目标、用户角色、功能需求、非功能需求和验收条件，作为系统设计、开发、测试、比赛评审和后续维护的共同依据。

### 1.2 项目背景

传统问卷工具通常能完成“创建和回收”，但在问卷结构设计、传播来源识别、低质量答卷治理、开放题总结以及结果解释方面仍依赖大量人工工作。本项目以问卷全生命周期为对象，将模板化设计、质量治理和 AI 数据洞察整合到同一工作台，降低问卷设计门槛，提高数据可信度和分析效率。

### 1.3 适用范围

- 校园调查、课程评价和社团活动报名。
- 员工满意度、培训反馈和候选人信息登记。
- 客户满意度、产品体验反馈和市场需求调研。
- 会议签到、信息采集和轻量级数据回收。

### 1.4 术语

| 术语 | 说明 |
|---|---|
| 创建者 | 注册并管理问卷、答卷、分析和导出的用户 |
| 填写者 | 通过公开链接或二维码提交答卷的用户 |
| 公开码 | 发布后生成的唯一问卷访问标识 |
| 有效答卷 | 未被创建者标记为无效的答卷 |
| 来源 | 公开链接、二维码或微信转发 |
| 填写会话 | 从打开问卷到提交之间的服务器端会话记录 |
| AI 洞察 | 仅依据真实统计数据生成、带证据引用的分析结论 |

## 2. 总体目标

1. 为非技术用户提供清晰、低门槛的问卷创建体验。
2. 建立从发布传播到回收分析的完整业务闭环。
3. 通过填写会话、重复提交限制和异常检测提高数据质量。
4. 通过结构化统计与 AI 辅助降低数据解读成本。
5. 支持标准数据格式导出，便于二次处理和归档。

## 3. 用户角色与权限

### 3.1 未登录访客

- 注册账号和登录系统。
- 通过有效公开链接访问正在收集的问卷。
- 按问卷设置匿名或实名填写。
- 提交答卷，并可选择提交填写体验反馈。

### 3.2 问卷创建者

- 管理本人账号资料。
- 创建、编辑、复制、发布、停止和删除本人问卷。
- 查看本人问卷的答卷、统计、来源和异常检测结果。
- 对异常答卷作有效或无效复核。
- 调用 AI 生成问卷、生成洞察并进行分析追问。
- 创建、下载和删除本人问卷的数据导出任务。

### 3.3 权限原则

- 账号功能和管理功能必须经过 Bearer Token 鉴权。
- 创建者只能访问自己拥有的问卷、答卷、分析和导出任务。
- 填写端只暴露处于“收集中”状态的问卷结构。
- 敏感配置只保存在服务器环境变量中，不下发到前端。

## 4. 功能需求

### 4.1 账号与身份认证

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-AUTH-01 | 使用名称、邮箱和密码注册 | 邮箱合法、密码不少于 6 位；重复邮箱被拒绝 |
| FR-AUTH-02 | 使用邮箱密码登录 | 成功返回访问令牌，失败显示明确提示 |
| FR-AUTH-03 | 维护登录状态 | 请求携带 Bearer Token；失效后回到登录界面 |
| FR-AUTH-04 | 查看和修改个人资料 | 支持名称、手机号码、所属组织 |
| FR-AUTH-05 | 上传头像 | 仅允许图片，前端限制 5MB，上传后顶部信息同步 |
| FR-AUTH-06 | 安全退出 | 清除本地令牌和用户缓存 |

### 4.2 问卷模板与创建

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-TPL-01 | 提供模板库 | 至少 8 套内置模板和空白问卷入口 |
| FR-TPL-02 | 按类别筛选 | 推荐、调研、信息收集、反馈、员工、活动 |
| FR-TPL-03 | 关键词搜索 | 标题、说明或标签匹配后显示结果 |
| FR-TPL-04 | 模板生成可编辑问卷 | 自动带入标题、说明、题目、选项和建议时间 |

### 4.3 问卷编辑

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-EDIT-01 | 编辑标题和说明 | 标题不能为空 |
| FR-EDIT-02 | 支持 7 种题型 | 单选、多选、问答、日期、评分、数字、电话 |
| FR-EDIT-03 | 题目增删与类型切换 | 新题可立即编辑，删除后编号连续 |
| FR-EDIT-04 | 选择题选项编辑 | 可增删选项，保存时必须存在有效选项 |
| FR-EDIT-05 | 必填设置 | 填写端和后端均执行必填校验 |
| FR-EDIT-06 | 问卷预览 | 可切换电脑和手机宽度，预览不提交 |
| FR-EDIT-07 | 公开页背景 | JPG、PNG 或 WEBP，最大 5MB；可更换和移除 |
| FR-EDIT-08 | 保存草稿和修改 | 持久化问卷及题目结构 |
| FR-EDIT-09 | AI 生成题目 | 根据自然语言生成结构化题目 |

### 4.4 问卷设置与生命周期

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-SET-01 | 草稿、收集中、已停止三态 | 管理列表和设置面板同步显示 |
| FR-SET-02 | 发布和停止收集 | 发布生成公开码、链接和二维码；停止后公开页不可访问 |
| FR-SET-03 | 匿名或实名填写 | 实名模式要求姓名和合法邮箱 |
| FR-SET-04 | 每人限填一次 | 匿名按提交 IP；实名按邮箱校验 |
| FR-SET-05 | 最长填写时间 | 1 至 1440 分钟，超时会话不得提交 |
| FR-SET-06 | 提交后显示答卷 | 开启后成功页展示本次回答摘要 |
| FR-SET-07 | 右侧设置抽屉 | 支持保存、取消、遮罩及 Esc 关闭 |

### 4.5 问卷管理与传播

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-MGT-01 | 管理页关键指标 | 问卷总数、累计回收、正在收集、平均完成率 |
| FR-MGT-02 | 关键词与状态筛选 | 可按问卷名称和状态查询 |
| FR-MGT-03 | 问卷复制 | 复制结构并生成新草稿 |
| FR-MGT-04 | 删除问卷 | 删除前确认，只能删除本人问卷 |
| FR-DIST-01 | 公开链接 | 可复制并分享 |
| FR-DIST-02 | 二维码 | 可扫码填写并下载图片 |
| FR-DIST-03 | 微信来源 | 微信内打开记录为微信转发 |
| FR-DIST-04 | 二维码来源 | 二维码链接携带来源参数 |

### 4.6 公开填写与提交

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-FILL-01 | 访问有效公开问卷 | 非收集中问卷返回不可访问提示 |
| FR-FILL-02 | 创建填写会话 | 记录开始、活动和到期时间 |
| FR-FILL-03 | 前后端双重校验 | 必填、单选数量和选项归属均由后端验证 |
| FR-FILL-04 | 记录元数据 | 来源、时长、IP、User-Agent 和提交时间 |
| FR-FILL-05 | 明确提交结果 | 成功或失败均提供可理解反馈 |
| FR-FILL-06 | 填写体验反馈 | 1 至 5 分、问题类型、补充说明，每份答卷限一条 |

### 4.7 数据分析与答卷治理

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-ANA-01 | 切换本人问卷 | 切换后所有指标同步刷新 |
| FR-ANA-02 | 数据总览 | 总答卷、有效答卷、平均耗时、完成率 |
| FR-ANA-03 | 7/30 天提交趋势 | 无数据时保持稳定布局 |
| FR-ANA-04 | 来源分布 | 链接、二维码、微信的数量和占比 |
| FR-ANA-05 | 逐题统计 | 选择题统计选项，文本题展示回答 |
| FR-ANA-06 | 答卷列表与详情 | 显示填写者、来源、时长、时间和每题回答 |
| FR-ANA-07 | 异常答卷扫描 | 从速度、作答比例、同位选择、文本重复评分 |
| FR-ANA-08 | 人工复核 | 可确认无效或恢复有效，不自动删除 |
| FR-ANA-09 | 体验反馈概览 | 平均评分、问题数量和反馈列表 |

### 4.8 AI 辅助能力

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-AI-01 | 自然语言生成问卷 | 结构化 JSON 经规则校验后进入编辑器 |
| FR-AI-02 | 真实数据洞察 | 输出关键发现、建议和证据，不编造数字 |
| FR-AI-03 | 分析追问 | 同一问卷和时间范围内保持对话上下文 |
| FR-AI-04 | 清空对话 | 清除当前服务器对话上下文 |
| FR-AI-05 | AI 失败处理 | 密钥、网络或格式问题均给出明确提示 |

### 4.9 数据导出

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-EXP-01 | Excel、CSV、JSON | 文件包含题目列与答卷 |
| FR-EXP-02 | 全部、近 7 天、自定义范围 | 日期完整且开始日期不晚于结束日期 |
| FR-EXP-03 | 可选元数据 | 包括答卷 ID、填写者、来源、时长、有效性和时间 |
| FR-EXP-04 | 导出任务记录 | 显示状态、行数、时间，支持下载和删除 |

## 5. 非功能需求

### 5.1 安全性

- 密码使用 bcrypt 单向哈希。
- 管理接口使用 JWT Bearer Token 鉴权。
- 所有管理查询校验资源所有权。
- AI Key、数据库密码和 JWT 密钥使用环境变量。
- 上传文件校验类型、大小并使用服务器生成文件名。
- 公开提交在后端执行必填、重复和选项归属校验。

### 5.2 易用性与兼容性

- 页面提供加载、空数据、失败和成功状态。
- 桌面与移动端均可浏览和填写。
- 支持主流 Chromium 浏览器最近两个主要版本。
- 生产数据库使用 MySQL 8.0 及以上。

### 5.3 可维护性

- 前端按视图、API、类型和公共组件分层。
- 后端按 Router、Schema、CRUD、Model、Config 和 Utils 分层。
- 接口采用统一 `code/message/data` 结构。
- 数据库提供初始化脚本，配置与源码分离。

### 5.4 性能目标

以下为验收目标，不代表已完成压力测试：

- 稳定局域网环境下普通管理页面 2 秒内完成首屏数据返回。
- 单份问卷支持不少于 100 道题。
- 列表接口分页，单次最大返回 100 条。
- AI 调用有独立等待状态，不阻塞其他业务操作。

## 6. 关键业务规则

1. 草稿不能通过公开链接填写。
2. 停止收集后公开链接不可用，重新发布后可继续收集。
3. 匿名问卷“每人一次”依赖 IP，在共享网络中存在限制，应在答辩中说明。
4. 填写时限从创建填写会话开始计算。
5. 风险分达到 40 分进入异常列表，但由创建者最终确认。
6. AI 分析只读取当前用户拥有问卷的聚合数据。
7. AI 结果是辅助建议，不替代人工判断。

## 7. 验收场景

### 7.1 主流程

注册/登录 → 选择模板 → 编辑题目 → 配置规则 → 预览 → 发布 → 获取链接/二维码 → 填写并提交 → 查看来源和趋势 → 扫描异常 → AI 洞察 → 导出 Excel。

### 7.2 异常流程

- 未填写标题或必填题时阻止保存/提交。
- 已停止问卷被访问时返回不可填写提示。
- 超时会话提交时提示填写时间已结束。
- 重复提交时提示仅允许每人提交一次。
- 非所有者访问分析时返回无权查看。
- AI 服务异常时显示明确错误，不影响核心问卷流程。
